# Implementation Plan: Pedagogical Improvement — Mathematical Fundamentals Course

**Branch**: `007-improve-math-pedagogy` | **Date**: 2026-09-13 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/006-improve-math-pedagogy/spec.md`

## Summary

Apply a uniform 12-section pedagogical template to all eight modules of
`teaching/mathematical-fundamentals/`, add one Observable JS (OJS) interactive
simulation per content module (Modules 1–7), improve the course entry page
(`index.qmd`), and create two new supporting reference pages
(`formula-sheet.qmd`, `learning-guide.qmd`). A companion amendment to
`.specify/memory/constitution.md` updates T-IV to accept OJS alongside
Shinylive as the approved interactive technology for teaching pages.

**Technical approach**: Content-only Quarto feature — no application code. All
deliverables are `.qmd` source files rendered to `docs/` by Quarto. The seven
OJS simulations run entirely client-side (bundled by Quarto at render time;
zero external CDN requests). Build gate is `quarto render` exiting 0 with OJS
widgets functional and no broken navigation links.

## Technical Context

**Language/Version**: Quarto Markdown (`.qmd`) + Observable JS (`{ojs}` code
blocks) — Quarto 1.x; OJS runtime bundled by Quarto at render time (no
external CDN)

**Primary Dependencies**: Quarto CLI; OJS stdlib bundled with Quarto
(`Inputs`, `html`, reactive cells — no npm/CDN dependency); KaTeX/MathJax for
math rendering (already configured); Quarto `.callout-*` blocks;
`quarto-ext/shinylive` extension already installed (not used by this feature)

**Storage**: Flat files — `.qmd` sources under
`teaching/mathematical-fundamentals/`; rendered HTML committed to `docs/`;
computation cache entries under `_freeze/`; two new `.qmd` support pages

**Testing**: `quarto render` MUST exit 0; manual verification that each OJS
widget renders sliders and updates reactively in the browser; link check via
all Continue links from Module 1 → Module 8; visual confirmation that all 12
sections appear in correct order in each module page

**Target Platform**: Static site served by GitHub Pages from `docs/` on `main`

**Project Type**: Static teaching site (Quarto) — content and interactive
client-side JS only; no runtime backend

**Performance Goals**: OJS slider interactions must be instantaneous (purely
client-side reactive computation). No server-side performance goals apply to
a static site.

**Constraints**: Prose wrapped at 80 characters; all math in LaTeX (`$...$` /
`$$...$$`); no inline `style=` / `<style>` blocks; no tracking scripts,
cookies, or external embeds; OJS runtime makes zero external network requests;
callout semantics per constitution §V; all learner-facing content in English;
`lang: en` front matter verified/set on every touched `.qmd`

**Scale/Scope**: 8 module files (restructured) + `index.qmd` (extended) +
`formula-sheet.qmd` (new, ~20–25 entries) + `learning-guide.qmd` (new, 4
subsections) + `_quarto.yml` sidebar additions + `constitution.md` T-IV
amendment; 7 OJS simulation blocks total (one per Modules 1–7)
